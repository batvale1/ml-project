# 👗 Review Decoder

## Порекомендует ли покупательница эту вещь?

> Классификация англоязычных отзывов покупателей интернет-магазина женской одежды.

---

## 📌 О проекте

| Параметр | Значение |
|---|---|
| **Тема проекта** | Review Decoder: порекомендует ли покупательница эту вещь? |

## 🎯 Цель проекта

Разработать текстовый классификатор, который по англоязычному отзыву покупательницы определяет вероятность того, что она **порекомендует** или **не порекомендует** приобретённую вещь.

Итоговая модель должна стать основой интерактивного сервиса, в котором пользователь сможет ввести новый отзыв и получить вероятность:

- **Recommend** — товар будет рекомендован;
- **Not Recommend** — товар не будет рекомендован.

---

## 💡 Постановка задачи

Интернет-магазины получают большое количество текстовых отзывов покупателей. Текст отзыва содержит информацию об отношении покупателя к качеству, размеру, материалам, посадке и другим характеристикам товара.

В рамках проекта будет исследовано, насколько точно можно определить факт рекомендации товара, используя прежде всего **текст отзыва**.

Задача формулируется как задача **бинарной классификации текста**:

```text
"The dress fits perfectly and looks amazing!"
                         │
                         ▼
                 Text classifier
                         │
                         ▼
                 Recommend: 96%
```

---

## 📊 Данные

В проекте используется датасет **Women's E-Commerce Clothing Reviews**.

Датасет содержит **23 486 анонимизированных англоязычных отзывов** покупателей интернет-магазина женской одежды, информацию о категориях товаров и готовую бинарную метку рекомендации.

**Целевая переменная — `Recommended IND`:**

- `1` — покупательница рекомендует товар;
- `0` — покупательница не рекомендует товар.

### 🔗 Датасет

[Women's E-Commerce Clothing Reviews — Kaggle](https://www.kaggle.com/datasets/nicapotato/womens-ecommerce-clothing-reviews)

---

## ⚠️ Ограничения

В основную модель не будут подаваться признаки:

- `Rating`;
- `Positive Feedback Count`;
- `Clothing ID`.

Основной акцент проекта — определение рекомендации по **тексту отзыва** и допустимым дополнительным признакам.

Обучение большой языковой модели не является обязательным и не должно становиться блокирующим фактором проекта.

## 2️⃣ Чекпоинт 2 — Исследовательский анализ данных

На этапе EDA планируется изучить структуру датасета и особенности отзывов.

Основные направления анализа:

- исследование баланса классов `recommend / not recommend`;
- анализ пропущенных значений;

- сравнение доли рекомендаций по категориям одежды;
- анализ коротких отзывов;
- анализ потенциально неоднозначных примеров.

Результаты EDA будут использоваться при выборе preprocessing и моделей.

## 3️⃣ Чекпоинт 3 — ML Baseline

На этом этапе планируется построить первые модели и определить базовый уровень качества.

### Dummy baseline

В качестве простейшей точки отсчёта будет использоваться:

```text
DummyClassifier
```

### Основная baseline-модель

Основной классический NLP pipeline:

```text
Review
  │
  ▼
Preprocessing
  │
  ▼
TF-IDF
  │
  ▼
Logistic Regression
  │
  ▼
Recommend probability
```

Связка **TF-IDF + Logistic Regression** позволит получить интерпретируемую вероятностную модель и станет основным baseline для последующего сравнения.

Дополнительно может быть исследован `LinearSVC`. В случае использования его результата в сервисе для получения вероятностей модель должна быть откалибрована с помощью `CalibratedClassifierCV`.

---

## 4️⃣ Чекпоинт 4 — ML-эксперименты

После построения baseline планируется провести серию дополнительных экспериментов.

### Нелинейные модели

Один из предполагаемых вариантов:

```text
TF-IDF
  │
  ▼
TruncatedSVD
100–300 компонентов
  │
  ▼
CatBoost / HistGradientBoosting
```

### Сравнение наборов признаков

Планируется сравнить два подхода:

```text
Модель A
Только текст отзыва
```

и

```text
Модель B
Текст отзыва + категория одежды
```

Это позволит определить, даёт ли информация о категории товара дополнительный прирост качества.

### Интерпретация результатов

Также планируется:

- определить наиболее важные слова для линейной модели;
- исследовать False Positive и False Negative;
- найти типичные причины ошибок;
- отдельно рассмотреть сложные и неоднозначные отзывы.

---

## 5️⃣ Чекпоинт 5 — Интерактивный сервис

На основе выбранной модели планируется создать сервис для анализа новых отзывов.

Пользователь сможет:

1. ввести английский текст отзыва;
2. при необходимости выбрать категорию одежды;
3. получить вероятность `Recommend / Not Recommend`.

Пример предполагаемого результата:

```text
Review:
"The dress looks beautiful but the material feels cheap."

Recommendation probability: 78%

Result: Recommend
```

Сервис должен использовать тот же preprocessing pipeline, который использовался при обучении модели.

Также планируется предусмотреть:

- обработку пустого ввода;
- ограничение чрезмерно длинных текстов;
- корректную обработку пользовательских данных.

В качестве дополнительной возможности сервис может показывать слова, которые сильнее всего повлияли на решение линейной модели.

---

## 6️⃣ Чекпоинт 6 — Deep Learning

На DL-этапе планируется использовать заранее подготовленные **sentence embeddings** и небольшую нейронную сеть.

Предполагаемый pipeline:

```text
Review
  │
  ▼
Sentence Embeddings
  │
  ▼
MLP
  │
  ▼
Recommend probability
```

Полученная модель будет сравниваться с классическим подходом:

```text
TF-IDF + Logistic Regression
```

Сравнение будет проводиться на одинаковой выборке и по одинаковым метрикам.

Fine-tuning `DistilBERT` рассматривается как дополнительный эксперимент при наличии необходимых вычислительных ресурсов и времени.

# 📐 Метрики качества

Основной метрикой проекта планируется использовать:

### **Macro-F1**

Также будут анализироваться:

- **F1 для класса `Not Recommend`**;
- **PR-AUC**;
- **ROC-AUC**;
- **Confusion Matrix**.

При расчёте `PR-AUC` класс **Not Recommend** будет рассматриваться как положительный.

Особое внимание классу `Not Recommend` необходимо из-за возможного дисбаланса классов: высокая `Accuracy` сама по себе может не отражать реальное качество модели на более редком классе.
